# Rendering test scenes

Small procedural and authored-asset scenes exercise the normal HeavenBench rendering path. The 17 procedural scenes require no Heaven assets and provide controlled geometric stimuli. The `asset-*` scenes load compact groups of original Heaven nodes, meshes, materials and textures to expose authored UV seams, normals, displacement, cutouts and animation. Use both layers to inspect one effect, compare its enabled and disabled states, and repeat the same check after a Filament rebase. A feature flag alone does not establish coverage: the scene must contain visible geometry and the actual material, texture, light or emitter inputs that activate the effect.

Select a scene with `--test-scene ID`, list the available IDs with `--list-test-scenes`, or set `render_test_scene` in a configuration file. Scene defaults form a configuration base; explicit JSON values override it. CLI scene selection applies defaults at that point in left-to-right argument processing, so subsequent options override them. Existing Heaven asset loading remains the default when no test scene is selected.

The engine-side scene builder owns procedural meshes, material records, lights and emitter inputs. The backend owns GPU resources and uses the same `MeshStore`, `MaterialInstanceCache`, persistent renderables, shadow maps, shared depth, feature classes and post-processing as a normal scene. Test textures and grass roots are explicit fixture inputs; they must not masquerade as extracted files or silently become role placeholders. Missing fixture inputs are errors or an explicitly recorded unsupported case, not a successful effect comparison.

## Real-asset layer

Select an `asset-*` scene with the same `--test-scene` or configuration key and provide an extracted Heaven data root or compatible asset pack. These scenes use the ordinary XML0 node walker, mesh loaders, material inheritance, texture loading, tessellation and animation paths. Catalog placement adds only a common rigid translation to an original node group; it preserves the node's internal transforms and the source mesh/material data. Fixture construction does not load the full world or copy proprietary assets into the repository. Missing node references, meshes or authored material bindings fail explicitly; the procedural factory rejects asset-backed IDs instead of substituting a generated scene.

The real-asset manifest is separate from the maintained procedural manifest. It records fixed camera poses, lighting hours, simulation steps and feature pairs. Capture metadata identifies `render_test_source_kind`, the loaded relative node sources, actual mesh/object/material counts and authored material bindings. Receipts fingerprint the asset data, loose sibling core definitions/textures where applicable, fixture source and renderer binary. Asset-backed and mixed selections must never claim `asset_data_used=false`. Successful receipts still require image inspection and retain the original-scene and physical-platform acceptance limits.

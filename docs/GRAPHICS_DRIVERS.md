# Graphics driver guidance

HeavenBench checks the driver used by the active rendering device once at startup. Software rendering, legacy Nouveau OpenGL, and recognized versions below the project recommendations produce a dismissible advisory. Driver details and guidance remain available in the sidebar. These checks do not block rendering, install drivers, make network requests, or determine whether the newest driver is installed.

## Project recommendations

Policy reviewed **2026-09-30**. These are conservative project baselines for upgrade advice, chosen from established driver releases. They are not vendor minimum requirements, a tested compatibility matrix, or claims that all earlier releases contain a particular bug. A version at or above a baseline is not proof of stability, performance, or current security fixes. Install the latest **compatible** package offered for the actual GPU, operating system and computer; legacy hardware may require an older supported branch even when HeavenBench shows an advisory.

| Active driver | Project baseline | Basis |
| --- | --- | --- |
| Mesa hardware drivers, including AMD RADV and Intel | 24.0.0 | Established February 2024 release, with Vulkan 1.3 support dependent on the particular driver. [Mesa release notes](https://docs.mesa3d.org/relnotes/24.0.0.html). |
| Mesa NVK | 25.1.0 | Mesa 25.1 made NVK with Zink the default OpenGL implementation on Turing and later NVIDIA GPUs. Current supported NVK GPUs have a conformant Vulkan implementation; NVK is not categorically experimental. [NVK documentation](https://docs.mesa3d.org/drivers/nvk.html). |
| NVIDIA on Linux | 550.54.14 | Established February 23, 2024 release that includes Vulkan and window-system fixes. [NVIDIA release page](https://www.nvidia.com/Download/driverResults.aspx/218826/en-us/nNew/). |
| NVIDIA on Windows | 551.61 | Established February 22, 2024 Windows release. [NVIDIA release announcement](https://www.nvidia.com/en-gb/geforce/news/february-22-2024-geforce-game-ready-driver/). |
| Intel on Windows | Build 101.5186 | Early-2024 baseline used in Intel's MWC 2024 platform validation. This compares the final two build fields, not the WDDM prefix. [Intel validation deck](https://download.intel.com/newsroom/2024/mwc/Press_Deck_Intel_vPro_with_Intel_Core_Ultra_Processors.pdf), [Intel version schema](https://www.intel.com/content/www/us/en/support/articles/000005654/graphics.html). |
| AMD vendor driver | No numeric baseline | The exposed internal Vulkan/OpenGL number cannot reliably be equated with an Adrenalin package version. Guidance points to compatible vendor/OEM updates without claiming the installed package is old. |

Versions are compared numerically, not lexicographically. Mesa development and release-candidate builds at the exact baseline count as prereleases; distribution package suffixes retain the underlying Mesa release comparison. NVIDIA accepts normalized two-, three- or four-component vendor versions. Intel Windows accepts either the two-component Vulkan build or the full four-component Windows driver number and compares the final two fields. Missing, malformed, unknown encodings and unsupported platform/version combinations remain informational and do not trigger an age warning. Android and other platforms receive device-manufacturer update guidance without desktop thresholds.

## Driver identity and limitations

The Vulkan backend obtains identity from its selected physical device and, where available, `VkPhysicalDeviceDriverProperties`. Vulkan explicitly makes `driverVersion` vendor-defined; Vulkan API version, driver version and conformance-test version are different values. Known encodings are decoded by the backend; unknown numbers remain unverified. A PCI vendor identifies hardware, not the active implementation: an NVIDIA GPU can use NVIDIA's userspace driver, Mesa NVK or Nouveau. [Vulkan physical-device properties](https://docs.vulkan.org/refpages/latest/refpages/source/VkPhysicalDeviceProperties.html), [driver properties](https://docs.vulkan.org/refpages/latest/refpages/source/VkPhysicalDeviceDriverProperties.html), [Khronos version decoding](https://github.com/KhronosGroup/Vulkan-Tools/blob/main/vulkaninfo/vulkaninfo.h).

OpenGL identity comes from cached vendor, renderer and version strings for the active Filament context. The check does not create another context or inspect an arbitrary first system adapter. Vendor-specific normalized versions are extracted only when the format is recognized; the complete original version remains available for diagnosis.

Software implementations such as LLVMpipe and SwiftShader execute graphics work on the CPU. Their results do not measure hardware GPU rendering performance. Select a hardware GPU, check driver installation and GPU access in virtual/remote sessions, then restart HeavenBench. Mesa itself, RADV, Intel Mesa, NVK, Zink, and an open NVIDIA kernel module are not evidence of software rendering. [LLVMpipe documentation](https://docs.mesa3d.org/drivers/llvmpipe.html), [SwiftShader project](https://github.com/google/swiftshader), [NVIDIA open kernel modules](https://github.com/NVIDIA/open-gpu-kernel-modules).

Legacy Nouveau OpenGL receives a conditional feature/performance advisory. Clock management and support depend on GPU generation and kernel; the application does not claim every Nouveau device has low clocks or recommend kernel-module changes. Check current NVK hardware/kernel requirements or a compatible NVIDIA driver before switching. Mesa currently documents Linux 6.6 or newer for NVK and the NVK/Zink transition on Turing and later GPUs. RADV is a normal supported AMD Vulkan implementation, not an inferior fallback merely because it is open source. [Nouveau power management](https://nouveau.freedesktop.org/PowerManagement.html), [NVK support](https://docs.mesa3d.org/drivers/nvk.html), [RADV documentation](https://docs.mesa3d.org/drivers/radv.html).

## Updating safely

On Linux, use the distribution's supported graphics packages and driver-selection tools, including coordinated Mesa, kernel and NVIDIA updates. Do not mix unrelated installer packages or change kernel modules based solely on this advisory. NVIDIA itself notes that distribution packages can integrate better with the rest of the system; Ubuntu documents its Additional Drivers/`ubuntu-drivers` path. [NVIDIA package guidance](https://www.nvidia.com/Download/driverResults.aspx/218826/en-us/nNew/), [Ubuntu driver installation](https://ubuntu.com/server/docs/how-to/graphics/install-nvidia-drivers/).

On Windows, check the computer manufacturer's supported graphics updates first, especially on laptops. Vendor selectors are available from [NVIDIA](https://www.nvidia.com/en-us/drivers/), [AMD](https://www.amd.com/en/support/download/drivers.html), and [Intel Driver & Support Assistant](https://www.intel.com/content/www/us/en/support/detect.html). Intel recommends preserving OEM customizations where applicable. A Microsoft Basic Display Adapter can indicate a missing vendor driver; Windows Update and then the manufacturer are the supported update paths. [Intel OEM guidance](https://www.intel.com/content/www/us/en/support/articles/000005481/graphics.html), [Microsoft Basic Display Adapter guidance](https://support.microsoft.com/en-us/windows/hardware/display-graphics/microsoft-basic-display-adapter-in-windows).

Unit tests cover exact baseline boundaries, Intel WDDM/build handling, malformed and overflowing input, Mesa prereleases and package suffixes, family/platform isolation, software rendering, and uncomparable AMD versions. Device tests remain necessary for actual driver installation, rendered output and performance; passing the offline policy tests establishes none of those outcomes.

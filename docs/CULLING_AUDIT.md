# Instancing and culling audit — October 9, 2026

This audit follows the reported off-camera grass and mesh work at the custom visual-ultra settings. The original workload contains 22,323,082 stored mesh triangles and 1,873,691 generated grass blades, so its rendered geometry is substantially denser than the original 623,503-triangle base scene. The implementation retains that geometry, foliage density, materials, displacement, wind and shadow settings.

## Findings and corrections

Explicit Filament `InstanceBuffer` draws have one culling box for the entire renderable; individual member transforms do not receive separate camera or shadow visibility tests. Previously, grouping by mesh and source order could combine distant placements. Groups now also use a deterministic 32-metre world-origin cell at startup. The hardware instance-count limit still applies, unmatched placements retain singleton draws, and reflected or noncanonical transforms retain per-placement handling. Groups remain persistent when members move across cells.

The old instanced box was calculated once with a fixed 16-metre allowance, while member transforms continued changing. Both visible and depth builders now refresh their aggregate world box when a member transform is dirty. They share the same grouping and bounds helpers. The union covers the selected ordinary primitives rather than unrelated or prepared surfaces of the mesh. Non-displaced groups retain the existing one-metre local allowance; ordinary displaced groups retain the prior 16-metre world allowance. The latter is an inherited policy, not a complete proof for arbitrary displacement amplitude and scale. Prepared displaced surfaces keep their separate envelope and homogeneous-coordinate guards.

Regular grass and massive foliage previously used one whole-island renderable per placement/category. A small visible part kept all of that island's blades eligible. Complete blades and flower cards are now partitioned spatially into bounded index ranges, targeting 8,192 roots per range and at most 64 ranges per source/category. Vertex bytes, oriented triangles, complete root population and materials are retained. Ranges share their source buffers and use independently measured, wind-expanded bounds. The depth proxies borrow the identical buffers and index intervals. The existing 650-metre island distance policy is unchanged.

An additional exact index-reuse experiment was rejected. Within each blade/card it reused fully byte-identical entries, reducing a seven-triangle blade from twenty-one to nine distinct references and a flower card from twelve to eight. Attribute/triangle equivalence, negative controls and native tests passed, but the tested ledge changed from 7.80 to 7.77 FPS and feature startup rose from 2,516.24 to 3,342.40 ms. It retained all vertex-buffer bytes and saved no uploaded memory. Source, profiles and eight captures are preserved under the rejected `indexed-candidate` evidence; the retained implementation only partitions complete original index blocks.

CPU-skinned meshes, including the over-255-bone fallback, previously lost the static-culling exclusion when GPU skinning was disabled or unavailable. MeshStore now reports skeletal source ownership independently of the GPU capability marker. Both builders and the backend exclude those sources from static instancing and rest-pose-box culling, matching the existing conservative GPU-skinned policy. Native tests move a CPU pose eight metres beyond its rest box and retain a static cull-enabled control.

Off-camera rendering is sometimes required: shadow maps use light visibility, and an object outside the camera can still shadow a visible receiver. The optimization leaves those objects in the scene and lets Filament perform each pass's visibility test. No camera-only scene removal or shadow-quality reduction is introduced.

Each profile excludes the first two seconds and measures at least sixty further seconds. Fixed-time captures are separate from timing and use the complete visual-audit input pack.

The host tests check complete, deterministic grouping and index coverage, transformed corner containment after movement/rotation/scale, conservative invalid-transform handling, wind extrema and a distant-meadow culling stimulus. ## Later directional cascade refinement

The later October 9 shadow optimization refines Filament's global directional caster range independently against each non-depth-clamped map's actual raster frustum. It preserves off-camera shadow casters and upstream VSM/PCSS receiver promotion; depth-clamped maps and explicit culling exclusions remain conservative. Native primitive/pixel controls, an original-policy negative control, matched full-scene measurements and short affected-path tablet traces are recorded in [the cascade checkpoint](PERFORMANCE_OPTIMIZATIONS.md#october-9-conservative-directional-cascade-culling). That later executable improves one Linux visual-ultra ledge workload by 5.57% at unchanged settings; it does not erase the earlier spatial grouping's mesh-only/reverse-view regressions or qualify all cameras.

## Further optimization candidates

The most promising next mesh experiment is Filament's automatic command merging after visibility: individual placement renderables could receive independent camera/light culling, with surviving compatible primitives merged afterward. Current project materials and shared geometry support an experiment without a vendor or material change, but CPU command cost and the actual workload need measurement before replacing explicit instancing.

Grass still stores twenty-one entries for a default blade. Compacting the immutable vertex stream could reduce uploaded memory while retaining all seven triangles and attributes; that is a separate storage/layout change requiring geometry and pixel equivalence tests. Repeating only the rejected startup-heavy exact alias scan is not justified by the current measurements.

Very large ordinary meshes and GPU-skinned geometry still follow their existing conservative culling exclusions. Replacing those guards requires proven shader/animation envelopes and native silhouette tests. Geometry subdivision budgets, authored LOD selection and cascade-shadow caching are separate changes; they are not silently changed in this audit.

CPU cloth has private mesh ownership, so different flag instances do not share deformation or enter static instance groups. Its ordinary upload nevertheless retains a rest-pose box plus the existing one-metre margin: per-frame CPU vertex updates replace positions/tangents without updating renderable bounds. Source review does not prove that envelope contains every simulated pose, and this audit did not observe a cloth disappearance. A separate dynamic-pose bounds path should address it rather than guessing another fixed margin. Grass initialization also retains pre-existing failure-path limits around allocation rollback and partial scene membership; normal-path owner teardown is covered by the native tests, but allocation-failure recovery is not certified here.

# Intel Vulkan startup and readback investigation

The November 10, 2026 investigation isolates intermittent startup device loss and stale HDR uploads to the CCS compressed-image path on Intel BMG G31 (`8086:e223`) with Mesa ANV `26.0.8-1ubuntu0.3` and Linux `7.2.6-070206-generic`. Native Vulkan validation reported no API or synchronization errors in the failing controls. This identifies a failing path in this installed driver/kernel combination; it does not establish which upstream component introduced the defect or a newer driver version that fixes this reproducer.

## Reproduction and isolation

The preserved original smoke executable has SHA-256 `158eab9dc45da18ca788e44cc3452e80e38c3d920b19fbbce75639ab0bc9a682`. Its glass fixture fails with seven fence errors and black FLOAT results. A separate full-rate fixture can reset the Intel RCS engine during shared pipeline initialization and then hang indefinitely. Debugging that hang locates the driver thread inside `CommandBufferPool::getRecording` / `wait`, while the application waits for pipeline initialization to finish.

One read-only GDB run observes successful initial glass readback submission/wait/map, followed by `VK_ERROR_DEVICE_LOST` (`-4`) from renderer and readback submissions and waits. Six failing readback pairs were observed before the probe's event limit; seven fence errors appear in its ordinary log. GDB subsequently encountered an internal assertion, so that capture is explicitly incomplete. The matching kernel report identifies an RCS reset in the exact inferior PID. Debugger timing can affect scheduling; this does not assign the same cause to every earlier fence failure without a matching kernel reset.

The new `linear_staging` native case separates FLOAT-to-RGBA16F uploads from lighting and FLOAT readback. It samples six cubemap faces into an unlit RGBA8 target. Independent binary16-exact channels identify the upload epoch, selected cube and face. Forty uploads at sizes 1, 5, 64 and 256 cover fresh images, queued writes, completed reuse candidates and retained in-flight resources. Sixteen pixel comparisons retain the existing two-byte error bound. The failing queued case contains the correct cube and faces but the previous upload's epoch, rather than random noise or a wrong sampler selection.

The memory-mask experiment does not disable the same behavior as `noccs`: ANV can retain logical CCS for VRAM-only allocations even when the allocation is not marked compressed. The driver debug option also prevents ISL from selecting CCS surfaces. These are distinct controls in the exact Mesa source, not interchangeable meanings of an uncompressed memory type.

## Compatibility policy

The retained workaround uses the core `VK_IMAGE_CREATE_ALIAS_BIT` capability for independently allocated single-sample color images on the exact verified Intel/Mesa identity. No image storage actually overlaps another allocation. In this Mesa version, that flag selects a surface without logical CCS. Before creating each affected image, the backend queries support for the exact format, type, tiling, usage and proposed flags, including its required dimensions, mip count, array layers and sample count. An unsupported combination fails explicitly instead of silently restoring the known-broken compressed path.

The policy preserves texture formats, resolution, cubemaps, mip chains, sampling, displacement, lighting and all rendering effects. Depth/stencil, multisample images, other adapters, OpenGL and other driver versions retain their ordinary image-creation policy. A once-only startup diagnostic identifies the active workaround. It changes an internal lossless compression optimization and can change memory traffic and performance; earlier VRS measurements belong to their preserved pre-workaround binary and must not be presented as measurements of this candidate.

`VK_EXT_image_compression_control` is absent on this device. The exact ANV source withholds genuine control for Xe2 because compression is selected through memory PAT state. Explicit DRM modifiers also restrict the supported image shapes, so they cannot replace the required cubemap/mip/MSAA workload generally. The retained path uses no unadvertised extension, global driver environment override, hardcoded memory-type index, extra CPU/GPU wait, material change or quality reduction.

## Independent source corrections

- `VulkanStagePool` creates host-written linear images in `PREINITIALIZED`, preserves reused images in `GENERAL`, and records `HOST_WRITE → TRANSFER_READ` after the row-pitch-aware copy and flush. Existing fence-backed resource ownership controls reuse. Creation/map/flush errors are checked in Release builds, and undefined destination layouts use the texture's defined default when restored.
- `VulkanReadPixels` records `TRANSFER_WRITE → HOST_READ` for the destination buffer, fixes the mip/layer layout lookup, and checks setup, submission, wait and mapping results. RAII rolls back unsubmitted resources. Failed submissions do not enqueue unsignalled-fence waits; failed mappings do not expose pointers. Cancellation still waits for submitted work. Only completion or device loss permits retirement; other uncertain wait failures terminate before unsafe cleanup.
- `VulkanCommands` checks end/submit/wait results before marking submission or recycling resources. Device loss now reports its operation and numeric result instead of spinning forever for an unavailable command-buffer slot.
- `ColorPassDescriptorSet::prepareAmbientLight` clamps a zero reflection mip count before unsigned subtraction. The default irradiance-only IBL binds a one-level dummy cube, so its shader maximum LOD is zero. Authored reflection levels, samplers, SH coefficients, exposure and intensity remain unchanged. This is a separate confirmed defect; correcting it alone did not cure the native CCS failure.

The [Vulkan synchronization examples](https://docs.vulkan.org/guide/latest/synchronization_examples.html#cpu-read-back-of-data-written-by-a-compute-shader) explain the separate host memory dependency; host coherence alone does not replace it. The [core alias flag contract](https://docs.vulkan.org/refpages/latest/refpages/source/VkImageCreateFlagBits.html) permits alias-capable images without requiring an actual alias pair.

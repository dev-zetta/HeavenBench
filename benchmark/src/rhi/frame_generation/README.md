# Native frame generation

The FSR provider executes AMD's actual optical-flow and frame-interpolation compute shaders. `Fsr31Vulkan::record` records into an application-owned Vulkan command buffer; presentation, frame pacing, latency policy and UI composition belong to the caller. It neither reads pixels back nor substitutes a blend between two images. The separate `FrameGenerationOutput` owns full-resolution SDR scene/UI targets and the extraction/composite draws; HDR is deliberately unavailable for the first integration.

The source is [FidelityFX SDK 1.1.4 / FSR 3.1.4](https://github.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/releases/tag/v1.1.4), pinned to commit `c6efa6bf7f2027b3ec94f28578bb5965eabb9e55`. `scripts/fetch_fsr31.py` checks archive SHA-256 `eff7e8e371b2d461b980f8c75583133f771e940ed7aa00779dbbaf6dd2f88746`, extracts source beneath `build/` and writes a per-file integrity manifest. Retain the SDK's `LICENSE.txt` and the SPIRV-Reflect license in distributions containing these components. The optional SDK is fetched explicitly; ordinary CMake configuration does not download it.

Build the standalone provider with `bash scripts/build_fsr31_provider.sh`. `HEAVEN_FSR31_SOURCE` and `HEAVEN_FSR31_BUILD` can select already fetched sources and an isolated build tree. Add `-DHEAVEN_FSR31_NATIVE_TEST=ON` to build the opt-in Radeon fixture, then run `build/fsr31-provider/heaven_fsr31_native_test`. The build requires Vulkan headers/loader, Python, glslangValidator and the project's normal Clang/libc++ toolchain on Linux. Renderer CMake integration uses `add_subdirectory` and links `heaven_fsr31_provider`; its shader generation produces 102 genuine FP32 GLSL permutations and reflection-derived SDK resource tables. Windows-only AMD swap-chain code and AMD's Windows-only shader compiler are omitted; the upstream algorithms remain intact.

The generated backend copy disconnects the Windows-only swap-chain callback, falls back from `vkGetBufferMemoryRequirements2KHR` to the promoted Vulkan core entry point, aligns the internal `alignas(32)` effect-context array and reserves its padding, and widens the opaque context reservation on platforms with four-byte `wchar_t`, keeping the SDK's private-context size assertion. Its allocation policy excludes AMD device-coherent/uncached memory types because their optional logical-device feature is not enabled; required memory flags must all match, and the unused breadcrumbs path follows the same exclusion. The global descriptor pool uses the actual six-entry array length, preserving its storage-buffer entry omitted by upstream's literal count of five. A forced include supplies the missing portable C math/declaration includes and bounded Microsoft string-copy equivalents on Unix. Originals under the fetched source directory remain unchanged. These changes are explicit exact-string transforms which fail configuration if the pinned source drifts.

`transform_fsr31_backend.py` adds two transactions to that generated copy. `CreatePipelineVK` owns every partial sampler, descriptor, layout, shader module and compute pipeline until successful creation transfers ownership; failure clears its output and rolls back the reserved layout slot. First-context backend setup similarly owns the global descriptor pool, uniform buffer, allocation and mapping until setup commits, releasing them and resetting the scratch header on failure. `CreateResourceVK` propagates a recursive upload-buffer creation error before scheduling its initialization copy; the context retains and unwinds the partial resource slots. The script is a CMake configure dependency. `heaven_fsr31_pipeline_lifetime_test` executes the actual transformed backend with fake Vulkan functions: all 46 pipeline allocation failure points, a failed creation returning a partial pipeline handle, all six global setup failures, four recursive upload-buffer failures, retry, successful ownership and teardown must leave no leaked handles. It does not create a device or execute GPU work. Both FidelityFX SDK and SPIRV-Reflect notices are installed with the optional provider.

The generated backend also has a private scoped imported-view policy. `Fsr31PrepareViewScope` defers view-ring rotation during FI Prepare while retaining all unregister input-layout/resource-index cleanup; final FI Dispatch advances once per provider record, and optical flow keeps its separate advance. This avoids retiring Prepare's views during the next unfinished source record. Scope restoration covers success, errors, exceptions and nesting. `heaven_fsr31_view_retirement_test` exercises the actual generated registration/unregister functions with fake Vulkan ownership, overlapping records and independent old-policy/caller-bound negatives. No source or shader under the fetched SDK is modified.

The provider requires Vulkan 1.1, enabled storage-image extended formats and formatless read/write, and compute subgroup basic/arithmetic/quad operations. All 102 initial shaders target Vulkan 1.1 / SPIR-V 1.3, matching Filament's logical instance; generation checks every module header and runs `spirv-val` against that environment when installed, recording validation coverage in its JSON receipt. The shaders use native subgroup widths and FP32, so they do not request a forced wave64 subgroup or FP16 features. The owner must provide a logical Vulkan 1.1-or-newer device and attest enabled logical-device features; physical-device support cannot prove their enablement. It must provide single-sample images, current-to-previous motion vectors, normalized perspective camera axes, depth convention flags and monotonic wall-time frame durations. Pixel-valued motion uses scale `{1,1}`; top-left normalized UV motion uses `{renderWidth,renderHeight}`. Display color is HUDless and already tone-mapped; the first SDR path uses `RGBA8_UNORM` encoded sRGB, `R32F` inverted Vulkan depth and `RG16F` motion.

The compiled permutations need 256 compute invocations per workgroup, X/Y/Z size limits of at least 256/16/4, and twelve storage-image descriptors per stage/set. These exceed some Vulkan 1.1 minimum guarantees, so the provider checks the actual physical limits and rejects unsupported dimensions before creating SDK resources. An infinite projection uses its exact rendered near plane, independently of the finite culling far plane. The provider substitutes the largest finite float for the SDK's far parameter in both prepare and interpolation calls; the SDK's reversed/infinite flag selects near-based reconstruction, while the finite sentinel avoids undefined intermediate arithmetic. Finite projections retain their actual near/far values.

All provider calls belong on the native backend thread, outside render passes. Sampled inputs may enter in `GENERAL` or `SHADER_READ_ONLY_OPTIMAL`; output enters in `GENERAL`. The SDK's unregister step restores each borrowed image to its original layout after successful recording. The caller supplies barriers into those states and discards a partially recorded command buffer on failure. Submit in order on the same queue and drain it before replacing or destroying the provider. Before provider record R (R >= 4), GPU work through record R-3 must have completed: the final dispatch advances its four-slot imported-view ring and retires that earlier slot. One record includes Prepare, optical flow and Dispatch, including reset records. History invalidation, a discarded command buffer and frame-ID changes do not prove completion. HeavenBench honors the stricter default two-frame Filament admission; standalone callers must enforce the documented completion bound themselves. A failed partial SDK record must be discarded and the provider drained/recreated before further recording. Camera cuts, resize, scene reload, pause/resume, dropped source frames and rejected submissions invalidate history. A first/reset dispatch seeds history and returns false: present only the real frame. A true return permits one intermediate frame, followed by the real source frame; it is not proof that the frame was actually displayed.

The native fixture independently checks a translating foreground's halfway position, finite output, invalid features/extents/axes/aliasing, source-ID discontinuity, explicit history invalidation and drained context recreation. It covers both floating-point inputs and the production SDR formats with inverted/infinite depth. It does not establish full-scene disocclusion quality, UI/presentation cadence, driver portability, Windows acceptance or performance. Generated presentations must be reported separately from rendered source frames, and a scored benchmark tour must keep frame generation disabled.

# Optional Windows Vulkan DLSS adapter

The adapter targets official [Streamline 2.14.1](https://github.com/NVIDIA-RTX/Streamline/releases/tag/v2.14.1). Fetch headers explicitly with `python3 benchmark/src/rhi/frame_generation/dlss_fetch_sdk.py`; the source archive SHA-256 is `34d6e8b70a641c734299a6430aa8ef5be7d7ba8de28a47186b5707e439bd645b`. The helper extracts only headers and the MIT framework license, records every file digest, checks cached integrity and never downloads runtime DLLs. Configure-time network access is unnecessary.

Configure the Windows renderer with `-DHEAVEN_ENABLE_DLSS=ON -DHEAVEN_STREAMLINE_HEADERS=/absolute/path/to/streamline-2.14.1-headers`. CMake verifies the existing header manifest without downloading files, then builds `dlss_provider.cpp` and `dlss_runtime_loader.cpp` in a separate C++20 static library with the verified SDK includes. The renderer and SDK-free public contract remain C++23. The pinned SDK's `sl_pcl.h` has an invalid `using to_underlying = std::to_underlying` branch when compiling C++23; using C++20 avoids altering vendor headers. The option defaults off, building a truthful unavailable stub on every platform. Set `HEAVEN_DLSS_PLUGIN_DIR` to the supplied signed-library directory and `HEAVEN_DLSS_PROJECT_ID` to the application's registered NVIDIA project identifier before launching the optional build.

The user supplies an explicit absolute directory containing signed production `sl.interposer.dll`, `sl.common.dll`, `sl.dlss_g.dll`, `sl.reflex.dll`, `sl.pcl.dll` and `nvngx_dlssg.dll`. The loader verifies the interposer with NVIDIA's official signature helper before loading it. Production Streamline checks plugin signatures internally. No DLL is bundled, copied into packaging or downloaded automatically by HeavenBench. Runtime distribution remains subject to the [DLSS SDK license](https://github.com/NVIDIA/DLSS/blob/main/LICENSE.txt), independently of the framework's MIT license.

Initialize Streamline before any Vulkan instance/device. The native integration must use either Streamline's optional creation proxies or the exact extensions, features and extra queues from `requirements()`, then install all mandatory surface/swapchain/acquire/present/device-idle proxies before creating a surface. The provider's manual requirements route and automatic creation route must never be combined, because the latter already creates and records SDK queues. The [official manual hooking guide](https://github.com/NVIDIA-RTX/Streamline/blob/v2.14.1/docs/ProgrammingGuideManualHooking.md) is the authority for these hooks.

`DlssPlatform` supplies the automatic creation route: construct it with explicit bootstrap options before `Engine`, pass it to the engine builder, and keep it alive through engine destruction. It uses Streamline's optional instance/device creation proxies, installs the eight mandatory BlueVK proxies after driver initialization and before surface creation, and adopts the SDK's internally recorded queue metadata. Its `present` method supplies matching Reflex present markers and polls SDK state. Native fallback retains an unavailable reason when optional initialization fails. BlueVK and Streamline are process-global; simultaneous Vulkan engines are unsupported while this integration is active. Selecting DLSS from an already-created ordinary or FSR engine requires backend recreation.

Every application frame needs one Streamline token. Call `begin_frame` before sampling input, then provide matching simulation and render-submit markers. Present markers must use the same token as the current constants. [Streamline Reflex](https://github.com/NVIDIA-RTX/Streamline/blob/v2.14.1/docs/ProgrammingGuideReflex.md) is mandatory for DLSS frame generation. Preserve its sleep and markers when the panel is hidden; propagate its registered latency-ping window message to the application event handling.

Before an intercepted native present, supply native depth, signed floating-point two-channel current-to-previous motion, postprocessed HUDless color, and full-resolution premultiplied UI with transparent zero outside UI. Camera/object/deformation/skinning/grass motion coverage must be complete. Images stay alive and unmodified until presentation finishes; the conservative adapter retains Streamline's blocking presenting-queue mode and refuses cross-queue image reuse. Matrices are unjittered row-major with the actual depth convention, motion scale and camera reset. Vulkan VSync and unqualified HDR are rejected. These requirements derive from the [DLSS-G guide](https://github.com/NVIDIA-RTX/Streamline/blob/v2.14.1/docs/ProgrammingGuideDLSS_G.md).

Unlike immediate FSR dispatch, DLSS consumes resource tags later during presentation. A native callback that temporarily transitions Filament images to GENERAL must tag the layout restored after its callback, together with actual image view/allocation/usage metadata. Borrowed handles valid only for one command submission are insufficient unless the owner also retains their images through asynchronous presentation and synchronization. The adapter's explicit coverage/lifetime/queue/color-space acknowledgements default false and cannot be inferred from a non-null Vulkan image.

Before resize/reload, suspend generation, clear tags and drain driver/backend/present work before retiring any tagged image. Before destroying Vulkan, drain and call `slShutdown`; keep the loaded module alive until all borrowed proxy function pointers are retired. SDK presentation counts combine real and generated presentations since the previous state query. They are separate from rendered FPS and do not establish display scanout or the number of generated frames that reached the monitor.

`dlss_contract_tests.cpp` builds a GPU-independent acceptance executable with `HEAVEN_DLSS_CONTRACT_TEST_MAIN` and the two provider source files. It checks unsafe lifetime, queue, UI, image, projection and multiplier inputs and inactive lifecycle behavior. These checks establish host contracts only. Signed Windows runtime initialization, supported NVIDIA hardware, temporal visual quality, resize/pause behavior and measured presentation/latency acceptance still require native testing; Linux and AMD hosts remain explicitly unavailable for this provider.

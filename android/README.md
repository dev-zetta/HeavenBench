# Android development APK

`scripts/build_android.sh` builds the renderer and SDL as shared libraries, compiles SDL's matching Java activity, and packages an installable, debug-signed APK. The native renderer is optimized. Release signing and publication are separate. Android device rendering, pause/resume, touch interaction, memory use, and GPU compatibility require device testing; a successful cross-build alone does not establish those properties.

The published 1.1.0 APK uses a different development signing certificate from the published 1.0.1 APK. Back up imported assets and user data before uninstalling 1.0.1 and installing 1.1.0; `adb install -r` cannot update that older release in place. The earlier 1.0.1 APK also used a different certificate from 1.0.0. Local builds can update installations signed with the same local debug key.

The Linux build host needs the renderer's normal Clang/libc++ dependencies, Java 17 or newer, and an Android SDK. Install the versions pinned in [versions.properties](versions.properties):

```sh
export ANDROID_HOME=/path/to/android-sdk
sdkmanager 'platforms;android-35' 'build-tools;35.0.0' 'ndk;28.2.13676358'
./scripts/fetch_dependencies.sh
./scripts/build_android.sh --abi arm64-v8a --jobs 6
adb install -r build/packages/HeavenBench-1.1.0-android-arm64-v8a-debug.apk
```

The helper downloads checksum-pinned SDL 2.32.10 and Gradle 8.13 into the ignored `build/` tree. Android Gradle Plugin 8.11.1 packages SDK 35 with minimum API 26. NDK r28c supplies the C++23 library and enables 16 KiB native-library alignment by default; APK signatures, ZIP alignment, and required package contents are checked before delivery. The pinned versions are reproducible inputs, not a claim that they are the latest releases. [AGP compatibility](https://developer.android.com/build/releases/agp-8-11-0-release-notes), [NDK r28 changes](https://github.com/android/ndk/wiki/Changelog-r28), [SDL Android integration](https://wiki.libsdl.org/SDL2/README-android).

Filament's host generators are built separately in `build/android-host-renderer/` and exported to `build/android-host-tools/` before the NDK cross-build. `--host-build-dir DIR` can reuse a compatible Linux build. Android native output follows the shared `build_paths.sh` convention, `build/renderer-android-arm64-v8a/`. APK assembly output is under `build/android-gradle/arm64-v8a/`; final APKs and SHA-256 files are in `build/packages/`. `--package-only` repackages already-built native libraries. `--abi x86_64` supports an emulator build but does not substitute for physical GPU testing. No source or committed material package is regenerated by this workflow.

The APK includes project resources and third-party license notices, and excludes proprietary Heaven assets. On the desktop, create a ZIP with the renderer's `--pack-assets` command, transfer it to the device, and choose **Import asset ZIP**. The app copies the selected archive using the Android document picker; it does not request access to all device storage. The ZIP may retain the asset packer's top-level directory. A failed copy, unreadable ZIP, or missing Heaven world file leaves the previous archive intact; full asset validation happens when the renderer loads the scene. For a custom GLM installation, set `HEAVEN_GLM_LICENSE_DIR` to its license directory; the default uses the Debian/Ubuntu `libglm-dev` notices.

For a reproducible optional profiler capture, pass string extras `microprofile` (a basename) and `microprofile_seconds` to the exported launcher, and optionally boolean `microprofile_visible`, then choose **Explore** or **Run benchmark** as usual. The launcher forwards only these profiler options alongside its existing storage and benchmark mode. The basename must be 1-80 ASCII letters, digits, dots, underscores or hyphens, starting with a letter or digit; output stays under the app's writable `profiles/` directory. The duration text reaches the ordinary native `--microprofile-seconds` parser unchanged, which requires a finite value in 0.1..3600 seconds and a `--microprofile` base; its default is 10 seconds. Missing extras preserve existing arguments exactly, and the renderer activity remains non-exported. Recording includes a separate startup trace and then the timed runtime capture, and a recorded benchmark tour is unscored.

```sh
adb shell am start -n app.zetta.heavenbench/.LauncherActivity \
  --es microprofile tablet-smoke --es microprofile_seconds 1.0 \
  --ez microprofile_visible true
```

Choose **Explore** for the existing low preview configuration. The capture writes `profiles/tablet-smoke.startup.json`, `profiles/tablet-smoke.startup.html`, `profiles/tablet-smoke.json` and `profiles/tablet-smoke.html` beneath the launcher-displayed storage directory. A standalone timed Explore capture exits after saving and draining its final samples. For interactive control testing, launch Explore without profiler extras and open Diagnostics → Microprofiler, then use Record and Stop; a manual Stop leaves the renderer running. Retain the existing configuration and render scale during profiling acceptance, record thermal state before and after, and verify the exported trace separately from manual touch/panel acceptance.

The native SDL bridge borrows SDL-owned argument strings through a separate pointer array when removing `--android-user-dir`. SDL later frees its original array using the original argument count; changing those pointers in place duplicates cleanup pointers and aborts normal exit. `test_native_bridge.py`, run by the Android helper, executes the actual entry with host JNI stubs and verifies renderer arguments, caller ownership, return propagation and the original-count cleanup.

The launcher offers **Run benchmark** for automatic camera playback and **Explore**. During playback the toolbar keeps **Cancel**, **Settings** and **Quit** accessible, including through scene fades. Android Settings sizes and label widths follow the actual font/style scale and fit below the toolbar; all six tabs remain interactive. A changed live setting, an explicit Reload or a successfully parsed Load cancels the running score before changing its workload; merely opening Settings, rejected/no-op live edits and pending reload edits leave playback running. Cancellation discards the incomplete score and keeps Settings open. Fresh configuration defaults remain balanced, original textures and 1280×720; Android rendering uses immersive fullscreen and the positive Activity SurfaceFrame pixel extent through explicit width/height arguments after the saved configuration. The private `--android-user-dir` bridge remains the first argument pair, before `--fullscreen`. The Activity owns the Surface; native Android startup does not negotiate it using desktop window resizing. The resolution picker offers only the actual Surface extent, and Android's display panel describes the fixed immersive mode. A reload normalizes pending dimensions and fullscreen state to the current drawable before rebuilding. A genuine drawable change or pause cancels an active benchmark and discards its result/timing window; foreground rendering recreates the swap chain after a positive drawable returns. The saved configuration file is not automatically rewritten. The native renderer runs in a separate app process and receives the app's writable directory through `HEAVEN_USER_DIR`. The device checkpoint below distinguishes the tested local APK from the older successful CI build.

For this lower-workload preview, preserve the existing configuration and copy [config-low-preview.json](config-low-preview.json) into the launcher-displayed app files directory as `config.json`, then close and relaunch the renderer with **Explore**. The file uses valid dotted keys, disables tessellation, generated ground relief/foliage and the expensive optional effects/material paths, and retains original textures plus GPU instancing/skinning. `quality_preset: "custom"` preserves unspecified defaults; it does not disable features by itself. Sun PCF shadows, authored fragment POM/normal maps, original scene geometry and loading work can remain.

`android_render_scale` accepts a finite number in **[0.125, 1]** and defaults to 1. The Activity reads it when creating the Surface, requests a smaller real buffer and maps absolute touch/mouse coordinates to that buffer; change it by relaunching the renderer. Native startup uses the resulting actual drawable dimensions rather than saved desktop width/height. `android_preview_fps` accepts an integer in **[0, 240]**; 0 disables the cap, and Android defaults to 30. It limits only interactive preview submissions: scored benchmarks, captures and profiles are uncapped, while the selected Surface scale still defines their real pixel workload. The supplied profile selects scale 0.375 and preview cap 40; it is an optional lower-quality diagnostic configuration, not a global default or a guarantee of 30 FPS in other views.

When the GPU cannot upload an original BC1/BC3/BC4/BC5 texture, the renderer decodes its complete mip chain to RGBA8 on the CPU; the same path supports direct BC7 textures. Color-space semantics and missing-channel defaults are retained. This increases startup work and texture memory use on affected GPUs. DDS cubemaps with GPU-supported compression use the validated face/mip layout. Unsupported compressed cubemaps are rejected with a diagnostic because CPU expansion currently handles a single 2D image and does not convert each cube face. Filament's procedural sky and lighting probes do not use this DDS cubemap path.

Configuration (`config.json`), the imported `assets.zip`, tessellation cache (`cache/`), and benchmark reports (`results/`) live under Android's app-specific external files directory, usually `/sdcard/Android/data/app.zetta.heavenbench/files/`; internal app storage is the fallback when external storage is unavailable. The launcher displays the actual directory. Storage is removed when the app is uninstalled. For a connected development device, use `adb pull /sdcard/Android/data/app.zetta.heavenbench/files/results` to collect reports and `adb logcat` to inspect renderer failures. [Android app-specific storage](https://developer.android.com/training/data-storage/app-specific).

The GitHub Actions workflow builds and uploads a development APK as a workflow artifact. It does not create a public release, run the scene on a GPU, or sign with a production key. Avoid distributing the debug key as a production signing identity.

APK assembly requires Android Lint to pass for both application code and generated SDL Java sources. [prepare_sdl_java.py](prepare_sdl_java.py) verifies the SHA-256 of three SDL 2.32.10 inputs before creating a build-tree copy with local Bluetooth/capture permission checks and private USB receiver registration. The downloaded source and native SDL library are unchanged. A different SDL revision fails closed until these integration changes are reviewed; staging regressions check source preservation, input drift, and reproducibility.

The manifest declares vibration and legacy Bluetooth access, plus the runtime Bluetooth-connect and microphone permissions used by SDL's existing native permission-request paths. Those runtime permissions are requested only if an application opens the corresponding Steam Controller HID or audio-capture path; ordinary video/audio playback does not prompt. Bluetooth and microphone hardware remain optional. USB permission callbacks use `RECEIVER_NOT_EXPORTED` on API 33+, and an application signature permission on API 26–32, following the [AndroidX compatibility strategy](https://github.com/androidx/androidx/blob/androidx-main/core/core/src/main/java/androidx/core/content/ContextCompat.java). Lint does not recognize that manifest-backed fallback, so only the pre-33 registration expression has a scoped `UnspecifiedRegisterReceiverFlag` annotation; the permission check is not suppressed and all generated glue is analyzed. Upstream compatibility and lifetime warnings remain visible. Device testing must still cover permission refusal/revocation, USB attachment, and controller/capture behavior. [Android Bluetooth permissions](https://developer.android.com/develop/connectivity/bluetooth/bt-permissions), [receiver export requirements](https://developer.android.com/about/versions/14/behavior-changes-14#runtime-receivers-exported).

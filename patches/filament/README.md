# Filament rendering extensions

`scripts/fetch_dependencies.sh` pins a public upstream Filament revision, the SHA-256 of `heavenbench.patch`, and the resulting Git source-tree ID. The patch travels with the HeavenBench source archive, so clean Linux, Android-host, and Windows/Git Bash builds do not depend on an unpublished fork commit. The script remains the single source of truth for these identities.

The current base is public Filament **v1.77.2**. The patch preserves HeavenBench's dual X11/Wayland Vulkan window integration, HDR10 swap-chain option and color-space selection, immediate presentation preference, and colored-penumbra numerical safeguards. HDR10 requests now fail if the surface cannot supply the required HDR color space: silently selecting SDR would display the application's PQ-encoded output incorrectly. The rebase retains upstream surface-loss handling and conditional debug-extension selection. Changes already supplied by upstream are omitted from the rebased patch. The patch is a full-index Git diff against the pinned upstream source, including binary changes if any.

Bootstrap verifies the patch hash before touching the dependency. It builds the patched source tree with a temporary Git index and checks its exact tree ID before checking out a deterministic local commit. The real index and tracked files remain unchanged if patch preparation fails. An existing clean rebased commit with the same tree is also accepted; its author, date, or commit message need not match the generated commit. Both staged and unstaged edits are rejected. A different checkout is preserved and reported rather than reset automatically.

Checkout refuses to overwrite ignored local files as well as ordinary untracked files. `.gitattributes` preserves exact patch bytes and forces LF for shell helpers, including checkouts with Windows `core.autocrlf=true`; otherwise the SHA-256 check or Bash startup would fail before the build. Regression fixtures exercise both line-ending behavior and recovery after an ignored-file collision.

To update Filament, first retain the existing dependency commit, rebase the rendering changes onto a reviewed public upstream revision, and test that source. Export its diff with `git diff --binary --full-index UPSTREAM REBASED --` into `heavenbench.patch`; update the public revision, patch SHA-256, and `git rev-parse REBASED^{tree}` pins together. Verify a clean bootstrap and a second idempotent invocation before committing the repository changes. Do not pin a local commit that a clean clone cannot fetch.

The user-authorized v1.77.2 update changes Filament's material package version from 75 to 77 and therefore requires intentional regeneration: `scripts/build.sh --materials-all --jobs N`. The helper first incrementally rebuilds `matc`, even if an older executable already exists, then compiles material packages and regenerates their embedded declarations and definitions. Review the committed `.filamat` changes and verify Vulkan/OpenGL rendering; a matching material version alone does not establish visual parity. Ordinary builds retain committed packages, and `--materials` still recompiles only changed material sources. Android and Windows consume the checked-in packages produced by the reviewed host compiler.

The offline bootstrap regression test uses small local Git repositories to exercise patch identity, deterministic commits, repeated invocation, interrupted initialization, local-edit preservation, and source-archive operation. No upstream network request or vendor-source modification is required by that test.

## Contact-shadow temporal stability

The September 30, 2026 user-approved contact-shadow fix changes `shaders/src/surface_shadowing.fs`. Rays use the unjittered `ssrUvFromViewMatrix`, matching the structure depth pass even when SSR is disabled. Native texture UV orientation is converted exactly once on Vulkan/OpenGL.

The October 1 rounded-stone report exposed a regression in the subsequent receiver-plane rejection (`ec8b818`): discarding hits on one triangle while accepting its noncoplanar neighbors revealed bright triangular patches. The earlier derivative-normal origin offset also introduced triangle-dependent sampling. Both mechanisms are removed. `common_shading.fs` and `surface_shading_parameters.fs` retain the actual triangle normal, computed before discard/divergent lighting, solely to recognize a contact ray entering its receiver at the origin. Such a ray is immediately occluded: marching its first dithered step can otherwise jump past the depth slab on steep bevels. Smooth lighting normals can admit light from below the actual surface; consistently retaining geometric self-shadowing is necessary. The previous fixture incorrectly demanded that such back-lit receivers stay unshadowed.

Contact ray tests now reconstruct bilinear depth and retain the nearest depth from the same four texels. Both depths must intersect the existing ray thickness: interpolation removes the nearest-texel staircase on continuous surfaces, while the nearest value rejects interpolation across separated silhouettes. This follows the technique described in [Tomasz Stachowiak's depth-raymarching notes](https://gist.github.com/h3r2tic/9c8356bdaefbe80b1a22ae0aaee192db). A relative `2e-6` allowance covers projection/reconstruction roundoff. Texture gather supplies all four values where supported; its coordinate is the footprint center, ensuring hardware coordinate quantization cannot select a different neighborhood from the FP32 interpolation weights; the ESSL 300 fallback uses four explicitly clamped `texelFetch` calls. [Vulkan documents the separate texture-coordinate precision](https://docs.vulkan.org/spec/latest/chapters/textures.html). No sampler-state change, extra depth target, feature toggle, ray-distance change or sample-count increase is involved.

The GPU fixture includes flat and curved receivers, smoothed normals, front-facing and grazing light, steep receivers that expose skipped immediate hits, three camera projections, and a separate contact-only occluder. It checks receiver acne, retained occlusion and consecutive-frame stability. Real-scene reproducers include `tests/visual/stone_contact_shadow.json` and `tests/visual/ledge_contact_shadow.json`; see `docs/VISUAL_AUDIT.md` for measured results and limitations.

**October 3 acceptance gap:** the current geometric-hit policy produces dark polygonal patches on the displaced cottage roof where smooth material shading and actual face orientation disagree. The earlier depth-marching package also shows them. The fixture establishes geometric occlusion and sampled temporal stability, not smooth-shading fidelity on every displaced mesh. This remains an open visual release blocker; see `tests/visual/roof_contact_shadow.json` and [the roof audit](../../docs/VISUAL_AUDIT.md#roof-tile-contact-shadow-mismatch). The later finite-Sun integration below is retained separately; experimental geometry substitutions remain unretained.

Only twelve lit, cloth or subsurface packages are intentionally regenerated: glass, grass, cloth, foliage-shadow, lit, lit-aniso, lit-clearcoat, lit-colored-penumbra, lit-doublesided, lit-twosided, subsurface and window. The other 21 packages retain their bytes. The public base remains v1.77.2; bootstrap verifies the updated distributable patch hash and resulting source tree. Android rebuilding remains deferred to physical-device testing.

The October 3 upstream/history audit fetched `main` at `70d2da5e9b7014e1a4207d737aa8dc41b59880a2` and confirmed that v1.77.2 remains the latest stable release. Upstream's contact-shadow function is byte-identical before our rebase, in v1.77.2 and in that fetched `main`; no newer shader fix was found. The roof polygons reproduce with the rebase-era opaque packages once our `38df114` receiver opt-in is active. The reviewed base and patch pins therefore remain unchanged. See [the bounded history controls](../../docs/VISUAL_AUDIT.md#filament-upstream-and-weekly-regression-audit).

## GTAO occluded mass and world-direction moment

The later October 8 correction represents nearby blocked directions rather than fitting a visible cone to the receiver's hemisphere. The horizon producer subtracts each visible arc from that slice's unoccluded receiver hemisphere, using uniform solid-angle area and first-moment primitives with the spherical Jacobian `abs(sin(theta))`. Blocked mass is normalized by `2*pi`, and the world-space blocked vector moment by `pi`; the full hemisphere therefore has mass one and moment equal to its normal. An unblocked receiver has zero mass and moment regardless of the difference between its reconstructed depth normal and its authored smooth or mapped shading normal. This avoids treating the receiver's own hemisphere as an additional nearby occluder without rotating real blockers into the shading-normal frame. The existing scalar diffuse obscurance, power, slice/sample counts, radius and thickness remain unchanged; the scalar and directional representations are distinct measures.

`frameUniforms.aoBentNormals` is zero when directional AO is absent, one for legacy unit bent normals, and two for occluded moments. Mode two is selected only for GTAO horizon mode with bent normals enabled. SAO, visibility-bitmask GTAO and builds with GTAO disabled retain mode one and their prior consumer path; the bitmask producer has no directional estimate and keeps its deterministic source-normal fallback. The existing authored/static specular-AO policy also remains independent. No AO feature, normal map, geometric specular AA, diffuse AO or multi-bounce compensation is disabled.

Mode two uses a two-layer RGBA8 array. Layer zero retains scalar diffuse visibility in red and packed depth in green/blue, adding blocked mass in alpha. Layer one's RGB stores the world blocked moment with `(128 + 127 * moment) / 255`, so exact zero is byte 128 rather than a half-byte midpoint. Intensity scales mass and moment together before storage. Zero-mass and sky samples supply a neutral moment before filtering, and sky clears have alpha zero; this prevents white render-target clears from becoming fictitious blocked directions. Bilateral filtering and upsampling use the same scalar-depth weights for both fields and preserve the vector's magnitude instead of normalizing it. The four-texel gather coordinate is the footprint center; the mobile ESSL fallback uses clamped `texelFetch` samples in the same order for scalar visibility, depth, mass and moment, fixing the previous mismatched fallback neighborhoods.

The consumer approximates blocked directions with a soft spherical cap. For mass `m` and moment `M`, it fits axis `M / length(M)`, aperture cosine `c = length(M) / m - 1`, and opacity `m / (1 - c)`. Scaling both fields by intensity preserves the fitted direction and aperture and changes only opacity for an exact valid cap. Quantized inputs clamp `c` to `[0, 1 - m]`; zero mass returns no directional occlusion, and dispersed fields with `length(M) <= m` use the existing scalar Lagarde estimate because they cannot fit a cap narrower than a hemisphere. The reflected specular cone intersection then attenuates the lobe with the fitted opacity. The full material still takes its existing scalar/authored-AO minimum and multi-bounce compensation, so the isolated screen helper is not the full outgoing-light model.

Eleven resulting `.filamat` packets change; foliage-shadow remains byte-identical, giving twenty-three preserved packets out of thirty-four. ## Portable CPU and GPU pass profiling

The October 9 profiler additions retain all twenty-four previously patched paths and add a runtime-gated observer below the existing tracing macros. At that profiler checkpoint, the full-index patch against public v1.77.2 had SHA-256 `ac1aaceab327a340c3800c86eff64aedc2cdfb6024f00746841a4214eadf6ba2` and reconstructed source tree `fd19d01ead0f05cc68664c0e292521d284414d9e`; the current pins additionally include the directional cascade refinement below. No project shader, material source or package-version change is required by this instrumentation.

`libs/utils/include/utils/ProfilerTrace.h` exposes the optional observer, complete CPU events, GPU samples, capabilities and a context containing application attempt/submission, native Filament frame, renderer, view and capture identities. `libs/utils/include/private/utils/ProfilerTrace.h` supplies bounded scopes, scoped context and the driver-thread adapter; `libs/utils/src/Profiler.cpp` implements them in the existing utility library. The common, Android and Darwin `private/utils/Tracing.h` headers retain their original native tracing behavior, including Android Perfetto arguments, while forwarding to the optional observer. CPU scope storage is bounded to 128 nested scopes per thread, copies borrowed scope labels and reports overflow explicitly. Callbacks run on their producer thread, borrow strings only for that call and must not allocate, block, throw or call graphics APIs.

`libs/utils/include/utils/JobSystem.h` and `libs/utils/src/JobSystem.cpp` keep the 64-byte Job layout and preserve the creation context through queued jobs and descendants in a fixed 16,384-entry sidecar (768 KiB). Named scene and froxel worker scopes therefore reach the portable collector with their original capture and frame identities; enabled capture also records job execution. Disabled job creation clears the capture marker without copying the full context, and disabled execution avoids installing a profiling context. `filament/include/filament/Renderer.h`, `filament/src/Renderer.cpp` and `filament/src/details/Renderer.{h,cpp}` add the owner-thread context setter, native frame updates, automatic renderer/view identities and queued capture boundaries, including standalone views. Capture acceptance occurs on the submitting thread, so disabling a capture while its commands are still queued cannot reinterpret those GPU samples as a later capture.

`filament/src/fg/FrameGraph.cpp` brackets each executed, non-culled FrameGraph pass with dedicated GPU timestamps and copied pass names. `filament/src/RenderPass.{h,cpp}` records actual command spans and the sum of the culler-visible input ranges executed in each FrameGraph pass; explicit instance groups count as renderables, not individual placements. Native draw submission in `filament/backend/src/{vulkan/VulkanDriver.cpp,opengl/OpenGLDriver.cpp}` counts submitted topology primitives, including instance multiplicity, and `draw_instance_invocations`, the sum of instance counts across executed draws. The latter can count a placement again in split primitives or shadow passes and is not a unique visible-placement count. These counters describe the timed pass; this version adds no individual-draw timers.

`filament/backend/src/GpuProfiler.h` owns at most 256 pass invocations per frame and sixteen frames in flight, with dedicated storage for 8,208 timestamps. `filament/backend/src/vulkan/VulkanGpuProfiler.h` checks the selected graphics queue's timestamp-valid-bit count and timestamp period, waits for no query in the normal path, and reads results only after their existing submission fence completes. Valid-bit wrap is handled relative to that frame's hardware origin; an ambiguous half-counter revolution or invalid ordering becomes an error. `filament/backend/src/opengl/OpenGLGpuProfiler.h` uses timestamp pairs rather than nested whole-frame elapsed queries. `opengl/OpenGLContext.{h,cpp}` and `opengl/gl_headers.{h,cpp}` expose GLES query-counter entry points; existing timer-query blacklists remain authoritative, and GLES disjoint notifications invalidate affected intervals without recycling their in-flight storage early. The driver headers own these optional adapters, and `filament/backend/src/Driver.cpp` supplies the common lifetime boundary. Dedicated query storage is created only after capture acceptance and is destroyed through the ordinary driver shutdown path.

GPU callbacks distinguish pending, available, unsupported, disjoint, error and dropped results; unavailable timestamps remain `-1`, and late available results retain the same pass and capture identities. Both APIs report an explicitly uncalibrated, frame-relative GPU clock, so the portable collector must not align it with the CPU steady-clock origin. Existing normal frame/tick polling and existing explicit finish waits drain pending queries after recording is disabled. This adds no forced GPU wait to normal capture. Capacity exhaustion is reported as dropped data, and drivers whose timestamp queries are unavailable or blacklisted remain unsupported instead of substituting CPU fence timing.

## OpenGL cached-program destruction

The later October 9 guard changes only `filament/backend/src/opengl/OpenGLDriver.cpp::destroyProgram` relative to that checkpoint. Before destroying the currently cached `OpenGLProgram`, it clears `mBoundProgram` and calls the existing backend-state `useProgram(0)`. The program allocator can reuse an object address; leaving the old pointer cached makes `OpenGLDriver::useProgram` mistake the replacement for the prior program and skip its lazy initialization, binding and descriptor setup. Clearing both the object identity and cached GL binding preserves ordinary destruction and lets the next program follow the normal setup path.
